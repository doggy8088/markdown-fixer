# 會員點數系統規格書

**文件版本：**v1.3
**最後更新：**2026-10-28
**撰寫者：**AI 助理（經 PM 審閱）

---

## 1. 背景說明：

目前會員點數分散在三套系統，客服查詢一筆點數平均要 4 分鐘。本專案目標是**整合為單一點數服務**，並提供 API 給前台與 POS 使用。

## 2. 目標與非目標

### 2.1 目標
- **統一帳本：**所有點數異動都寫入同一個 ledger
- **即時查詢：**P99 查詢延遲 < 200ms
- **可稽核：**每一筆異動都能追溯到來源訂單

### 2.2 非目標
- 不處理點數兌換商品的物流
- 不改動既有會員等級規則

## 3. 名詞定義

| 名詞 | 定義 |
| --- | --- |
| 點數（Point） | 會員可用於折抵的虛擬貨幣，1 點 = NT$1 |
| 帳本（Ledger） | 只能附加（append-only）的異動紀錄 |
| 凍結點數 | 已預扣但尚未確認的點數 |

## 4. 功能需求

### 4.1 點數累積

1. **觸發條件：**訂單狀態變為「已付款」
2. **計算方式：**
   - 一般會員：消費金額 × 1%
   - 金卡會員：消費金額 × 2%
   - **例外：**運費與手續費不計點
3. **入帳時間：**付款後 7 天（鑑賞期結束）

### 4.2 點數折抵
1. 每筆訂單最多折抵訂單金額的 50%
2. 折抵時先凍結，訂單成立後才扣除
3.**注意：**取消訂單時，凍結點數要在 5 分鐘內釋放

#### 4.2.1 折抵順序
* 先扣即將到期的點數
* 再扣活動贈點
- 最後扣一般點數

### 4.3 點數到期

- **到期規則：**每筆點數自入帳日起 365 天到期
- **通知：**到期前 30 天、7 天各發一次推播
-  **批次：**每日 03:00 執行到期批次

## 5. 非功能需求

| 項目 | 需求 | 備註 |
|--|--|--|
| 可用性 | 99.95% | 不含計畫性維護 |
| 延遲 | P99 < 200ms | 查詢 API |
| 一致性 | 強一致 | 扣點不可超賣 |

## 6. API 草案

```yaml
POST /points/hold:
  body: { member_id, amount, order_id }
  returns: { hold_id, expires_at }
```
